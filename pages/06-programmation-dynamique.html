CHAPITRE 5

Programmation Dynamique

La programmation dynamique est une méthode exacte qui transforme un problème difficile en une suite de sous-problèmes mémorisés. Pour le TSP, elle ne rend pas le problème polynomial, mais elle réduit fortement le coût par rapport à l'énumération naïve de toutes les tournées.

Idée centrale : au lieu de recalculer plusieurs fois le même chemin partiel, on garde en mémoire la meilleure distance pour atteindre une ville donnée après avoir visité un ensemble précis de villes.

🧠 Principe d'optimalité de Bellman

Le principe d'optimalité affirme qu'une solution optimale est composée de sous-solutions optimales. Autrement dit, si une tournée optimale arrive à une ville j après avoir visité un ensemble S, alors le chemin utilisé avant d'arriver à j doit lui aussi être optimal pour ce sous-problème.

Optimal = meilleur choix courant + solution optimale du sous-problème restant

📐 Algorithme de Held-Karp

L'algorithme de Held-Karp est l'application classique de la programmation dynamique au TSP. On fixe une ville de départ, puis on calcule progressivement le meilleur coût pour atteindre chaque ville après avoir visité certains sous-ensembles.

État DP : DP[S][j] représente le coût minimal d'un chemin qui part de la ville 0, visite exactement les villes de l'ensemble S, et termine dans la ville j.
DP[S][j] = mini ∈ S, i ≠ j ( DP[S \ {j}][i] + d(i,j) )
Réponse finale = minj ≠ 0 ( DP[Toutes les villes][j] + d(j,0) )

🔄 Étapes de résolution

Pipeline Held-Karp

1. Fixer la ville de départ
2. Initialiser les sous-ensembles
3. Remplir la table DP
4. Fermer la tournée
5. Reconstruire le meilleur chemin

💻 Pseudo-code simplifié

pour chaque ville j ≠ 0 : DP[{0,j}][j] = d(0,j)
pour chaque taille k de 3 à n :
  pour chaque ensemble S contenant 0 et |S| = k :
    pour chaque j dans S, j ≠ 0 :
      DP[S][j] = min(DP[S-{j}][i] + d(i,j))
retourner min(DP[V][j] + d(j,0))

📝 Conclusion du chapitre

La programmation dynamique apporte une méthode exacte plus intelligente que la force brute. Elle reste exponentielle, donc limitée pour les grandes instances, mais elle constitue une base théorique essentielle pour comprendre les compromis entre optimalité garantie et temps de calcul.
